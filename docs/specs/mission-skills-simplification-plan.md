## 1. 本轮要交付什么

让 Align 用更少的固定对话步骤完成必要对齐，让 Brief 清楚保留可执行的结果合同，并取得新 Agent 实际接手完成任务的证据。删除有重叠或无收益的规则，同时保留来源、授权、兼容性和实质验收能力。

完成后应能回答三个具体问题：精简有没有改变应保留的行为；完全明确的委托能否减少一次无必要确认；精简后的合同相对现版和极简委托提示，能否在选定任务中维持交付质量并降低交接负担。小规模实验不支持“普遍最优”或“充分发挥所有最新模型”的结论。

保留以下产品约定：

- Align 对齐、Brief 写结果合同、Review 检查兑现情况，继续使用三个 Skill。
- 一个 Mission 对应一个可独立裁决的结果；Mission 0 只处理真实集成结果与接缝。
- Brief 的四项核心：`Outcome`、`Success`、`Evidence Required`、`Boundaries`。
- 来源保持实际权威状态，重要信息有持久去向，执行者保有实现路线选择权。
- 未委派的重大选择、适用的外部权限条件、明确要求的人类决定仍须解决。
- Review 保留当前产物身份、证据适用范围、必要独立性及三态裁决。
- Codex 中 Align 可隐式发现，Brief、Review 保持显式调用；运行时仍为两、四、两个文件。

不新增总路由 Skill、共享规则框架、模型专用正文或通用评估平台；不设字数削减比例。模型与推理档位留在实验配置，测试材料留在维护者目录。保留上一轮规格和原始运行作为历史记录。

## 4. P1：先精简写法，保持现有产品语义

### Align

- 缩短 description，使其聚焦“在 Brief 前对齐不清楚或有争议的委托”。可先试 `Align an unclear or contested Mission commission before briefing.`；以真实发现行为决定是否采用，不能仅按字符数判断。
- 将五阶段行程、逐阶段完成判据及逐项提问动作收敛为必要信息、重大缺口、完成条件。保留 Mission 适用性、拓扑、来源与委派的领域判断，不规定每个问题都必须展开全部维度、选项和推荐。
- 合并最终摘要与交接。已有摘要可直接承担交接功能，只补必要来源、持久位置和下一产品入口；不重复输出同一份结果与边界。
- 这一阶段仍遵守现版初始采纳规则。明确修正、含糊回应、有限委派、外部条件及取消原请求的含义不变。

### Brief 与 Review

- 合并 Brief 的重大未决选择／授权语义冲突停点，将同一规则保留在一个位置。
- 将结尾的 `blind handoff check` 明确为交接就绪判断：合同可恢复、来源可定位且状态明确、裁决依据清楚、路线可自主选择。作者自检不能被称为已完成独立盲读；真正独立阅读留在评估或合同确实要求的场景。
- 保留计划与 Brief 的交付物边界，该条有重复故障依据。继续按条件读取两个 reference，不为缩短主文件而机械拆文件。
- Review 正文原则上不改。只有本轮运行发现可复现的实质缺陷，才另列最小修正及对应案例。

**定向验证：** B 与 S1 使用相同旧规则、模型和输入，覆盖清楚委托、真正歧义、明确修正、委派、外部权限、持久保存、普通请求不误触发，以及 Brief → Align → Brief。优先复用第 7 节案例，不新增同义测试。改变 description 后必须检查真实 Loader 行为。

**退出条件：** 没有丢失产品规则、出现新的无必要提问或重复交接；文本重叠实际减少。若只能测得更短，结论就限定为维护与阅读上的精简，不声称模型成本已下降。导致退化且没有必要收益的改动直接撤回。

## 5. P2：单独改变“首次必须确认”的规则

这一阶段修改现行产品规则，应先同步规格和评估预期，再运行候选。目标规则是：**用户的明确指令或有效委派已经确定全部重大决定，且 Agent 综合没有增加新的实质解释时，可直接视为已对齐并交接。**

“重大”仍指会改变结果、成功含义、边界、权限或结果拓扑的选择。实现位置、工具和可安全调查的根因不因此成为用户必须决定的事项。Agent 的建议、沉默或含糊回应不能产生新授权。

| 输入状态 | S2 预期行为 |
| --- | --- |
| Safari Enter 回归、目标行为及 Chrome／鼠标兼容边界均已明确，没有新增产品选择 | 给出精练对齐结果并交接，不要求用户再采纳自己的原指令。 |
| 用户明确要求“先给摘要，等我确认” | 提供摘要后等待；用户要求的确认仍有效。 |
| 用户已委派某项选择，Agent 在其范围内完成选择 | 记录所作决定并继续；不扩展到未委派的产品或权限事项。 |
| 用户仅说“差不多”或提出试探性建议，仍有重大选择未决定 | 只追问该缺口，不把含糊表述解释为采纳。 |
| 用户完整修正一个部分并明确接受其余内容 | 更新受影响内容后交接；不重新确认未变部分。 |
| 新修正带来未解决的权限、兼容或集成结果冲突 | 保留其他已定事项，只处理新冲突。 |
| 已调用 Brief，为消除歧义进入 Align | 对齐后恢复同一 Brief 请求，不要求新调用。 |
| 只调用 Align；或者原请求已取消 | 前者交付对齐结果和适用的下一入口；后者遵从取消，不扩大成实施。 |

先修改 `docs/specs/mission-align.md` 中的现行规则，并在 `CONTEXT.md`、README 的有关描述和示例中同步；再更新 `evals/mission-align.md`、pack rubric 及受影响接缝。保留历史决定及变更缘由，不回写旧运行输出。

`a-10000001` 应从“请求首次采纳”改为检验直接交接。对 `a-1000000c/d/15/16` 等多轮案例逐项判断：要检验等待与采纳，输入必须确有未决重大选择，或明确要求先确认。不能用后续脚本假定 Agent 一定先问；也不能把本来存在真实歧义的案例一律改成直接通过。

冻结新预期后，以同一套新标准比较 S1 与 S2。S1 因忠实执行旧确认规则而多问一次，应标记为产品规则差异，不能归因成模型失误。真正的少问但误解、漏问或越权均判为退化。

**退出条件：** 清楚委托的指定探针省去初始重复确认；必要问题、委派范围、明确要求的确认、局部修正和原请求恢复全部成立。若有问题，先辨别是规则含糊、案例不真实、裁判误判还是运行时缺陷，再修对应层。

## 6. P3：让新 Agent 实际接手并完成

现有 `run_mission_brief_blind.py` 要求只读和解释，继续保留其用途。真实执行使用候选实际生成的合同和持久材料，在新上下文中修改隔离任务工作区、运行交付，再由独立上下文的 Review 检查。优先复用现有 harness；缺少这条路径时只增加一个薄入口，不复制隔离、会话采集和身份记录机制。

### 任务与对照

在改写候选前确定两个小型可运行任务的输入、判据与用户答复事实，保留作执行验证，不用于逐句调 prompt：

| 任务 | 种子与交付 | 要暴露的问题 |
| --- | --- | --- |
| T1 明确的小型兼容修改 | 一个已有命令行程序，增加机器可读输出；默认人类输出、退出码和错误行为继续兼容。用真实命令调用验证。 | 无必要确认、过重合同、额外文件与测试，以及省略旧用户行为。 |
| T2 混合来源与授权修正 | 一个小型本地导出程序及其消费者，输入包含已采用决定、候选方案和一次有价值的调查；随后明确修正格式兼容要求。执行权限限于本地，外部发布条件可用隔离记录检查。 | 建议升级为命令、调查丢失、旧版本约束残留、授权交接失败，以及“读懂了但没有做完”。 |

优先从现有混合来源和修正 fixture 派生；它们没有可运行目标时，只补上述最小程序和确定性检查。测试外部边界用隔离替身，不连接真实发布目标。成功标准、隐藏验收输入和答复事实在运行前冻结；后续答复只提供同一用户已持有的事实，不因候选而暗示正确路线。

每个任务比较 B、S2、M 三组。B、S2 使用各自 Align／Brief；M 用一段简短委托提示完成相同的对齐与合同产物，不加载这两份 Skill。三组得到相同原始来源、用户授权、工具环境与交付要求，不能将“一步直接改代码”与“三阶段交接”当作同一成本对照。

执行 Agent 的指令与模型固定；Review 也固定使用同一份未改正文和相同验收范围。因此这个对照测量的是 **Align／Brief 对交接和交付的增益**，不单独证明 Review 比极简审查提示更优。

新执行者只接收合同、被保留的持久来源、目标工作区与执行委托，不接收原作者对话。审查者接收原始验收要求、当前产物和可追溯证据，不接收候选标签、疑似缺陷、预期裁决或作者解释。核对原始要求时同时检查合同是否遗漏承诺，不能仅按被削弱的合同给通过。

### 数量、指标与判定

首轮固定为 2 个任务 × 3 组 × 2 次独立运行，共 12 条完整链路；保留全部结果，不重试到通过。运行顺序交错，记录异常与缓存等条件。模型访问失败可以另行重跑受影响链路，但原记录仍保留并标为基础设施问题。

| 指标 | 记录方式与用途 |
| --- | --- |
| 实际完成与关键承诺 | 确定性检查、实际使用和 Review 原始观察；这是接受候选的首要依据。 |
| 信息与权限 | 重大约束遗漏、来源状态错误、未授权动作分别记录；不能用平均分抵消。 |
| 对话负担 | 无必要确认、重复调用、真正必要的问题分别计数；说明具体判定理由。 |
| 执行返工 | 因合同遗漏或歧义导致的回问、重查和返工；与正常实现调查分开。 |
| 成本 | 可取得的输入／输出 token、工具调用和端到端耗时；缺失值记不可取得，不以词数替代。 |

候选在指定任务中须完成全部重大承诺，无新增越权或信息损失；确认调整须在目标探针中产生预期行为。结果波动或 M 相当时如实报告，不以小样本宣称统计非劣或普遍效率提升。M 同样有效意味着这些任务上的额外价值未被证明，应缩小收益表述；只删除已有证据表明多余的部分。

若发现实质失败，先定位再做一次最小修正，并在新版本下重跑受影响配对；这属于新的迭代，不能替换首轮失败。无需为成本差异不显著而持续加样本。
