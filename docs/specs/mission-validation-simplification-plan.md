目标：验证能回答本次修改是否改善或损害实际结果，并在证据足够时结束。保留真实边界与可信采集，移除默认全量、历史门槛和过程偏好。

## 实施顺序

- [x] **统一默认规则。** 在 `EVALS.md` 说明按变更选择验证、结果判定和停止条件；README 与三个 Skill 的评估说明引用它。全量案例、盲交接、独立 Closure 按具体疑问选用，不再作为每次修改或安装的共同前置条件。

- [x] **精简实际交接试跑。** 删除未使用的自动补答与其包装逻辑；分别报告采集完整性、阶段判定、实际命令验收和 Review 交付裁决，不以阶段评分偏好合成发布结论。补入已观察到的 CLI 兼容反例。
