# Mission Skills 与最新模型指南的对照评估

核查日期：2026-09-05。受审版本：`56659e74249b0b8a0cfb4e4b937f65d4b2887524`。范围为三份运行时 Skill、两个按需引用、调用元数据、产品说明及相关评估证据。本次只新增研究与评估文档，没有修改或重新安装运行时 Skill。

**总体判断：核心设计符合两家官方推荐，对强模型的推理、现场判断和自主选路比较友好；Astra 已有局部有效性证据。存在可以合并的防御性重复，但没有充分证据认定现版已经被规则堆积拖垮。“能完成所定义的产品”有支持，“充分发挥最新最强模型、比极简提示更有效”尚未被证明。Claude 的宿主兼容和行为验证仍有缺口。**

**本次使用的“最新”依据。** OpenAI 官方当前指南明确为 GPT-6 Astra，并指出它对 Skill 指令更敏感，可能因冲突而提前停下，也可能过度澄清、过度验证。Anthropic 当前高难推理与长程代理型号为 Claude Fable 5.1，官方标记 2026-09-01 发布；Mythos 5.1 同级但限邀请访问，多数任务的默认建议仍是 Opus 5。“最强”在这里采用厂商对高难任务的定位，不代表本仓库上的独立排名。[OpenAI 当前型号指南](https://developers.openai.com/api/docs/guides/latest-model)、[Fable 5.1 官方说明](https://platform.claude.com/docs/en/models/fable-5-1/overview)

官方文件与社区材料的详细适用范围见[来源研究](2026-09-05-anthropic-community-guide-sources.md)。社区部分采用 HumanLayer 作者 Kyle、Simon Willison 本人的指南及 ETH Zurich／LogicStar.ai 作者的原始论文，作为有出处的工程经验与研究，不当作厂商规范或最新模型的直接实验。

**符合推荐的地方，主要是设计本身。**

1. **任务边界清楚。** Align 负责对齐，Brief 负责可交接的结果合同，Review 负责检查兑现情况。单项 Skill 没有包办需求、架构、实现和发布。四项 Contract Core 提供稳定输出接口，具体实现交由执行者判断。这符合 OpenAI 对单一职责、明确输入输出的建议。[OpenAI Build skills](https://learn.chatgpt.com/docs/build-skills)
2. **给模型的自由度合适。** [Brief 第 16 行](../../SKILL.md:16)及[第 46 行](../../SKILL.md:46)把目标与已知事实保留下来，把可调查的根因、改动位置和架构留给现场 Agent；[Review 第 35 行](../../mission-review/SKILL.md:35)让模型选择足以挑战剩余承诺的低成本检查。它们约束交付结果，没有逐步规定模型必须怎样推理。Anthropic 推荐按任务脆弱性和变化程度分配自由度，开放式审查可以保留判断空间。[Anthropic Skill authoring](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
3. **按需加载真实存在。** [Brief 第 31 行](../../SKILL.md:31)先判断当前分支，再加载 Mission 0 或 source-fidelity；维护者文档、评估脚本、失败档案不随运行时安装。不能因为整个仓库文档多，就把它们全部计算成每次模型负担。[README 安装范围](../../README.md:164)
4. **验证检查真实结果。** [Review 第 37 行](../../mission-review/SKILL.md:37)限制证据能证明的范围，第 43 行按需使用独立上下文，第 47 行给出停止条件，第 55 行排除未委托的更高标准。三态裁决允许承认不确定性。这些是 Skill 的核心价值，不能作为“防御性文字”整体删除。
5. **当前版已处理新模型常见的停顿。** [Align 第 84 行](../../mission-align/SKILL.md:84)允许明确修正同时采纳其余摘要，第 106 行恢复仍有效的原请求；[Brief 第 97 行](../../SKILL.md:97)让 Agent 自行选择已授权的保存位置；[Review 第 10 行](../../mission-review/SKILL.md:10)保留先审后修的连续性。其方向与 Fable 5.1 对完成原请求、保留范围、减少已授权步骤重复询问的建议相符。[Fable 5.1 prompting](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1)

三份主文件分别为 Brief 108 行／约 1,373 个英文词、Align 108 行／约 1,280 词、Review 79 行／约 942 词；两个引用合计 63 行／约 592 词。统计使用 `wc -l -w`，不是 tokenizer 成本。它们没有接近官方建议的 500 行组织阈值，但低于阈值不等于每句话都有用；一次对齐后进入 Brief 也可能累计加载两份正文。四五步工作流程不是强制思维链，Markdown、三态标签、英文正文也不是新模型不友好的证据。

**最明确的兼容缺口：手动调用只在 Codex 宿主上落实。**

[Brief 元数据](../../agents/openai.yaml:6)和[Review 元数据](../../mission-review/agents/openai.yaml:6)使用 `allow_implicit_invocation: false`，两份 `SKILL.md` 的 frontmatter 则只有名称与描述。Claude Code 的官方默认是用户和模型均可调用，手动专用由 `disable-model-invocation: true` 或相应宿主设置控制。没有官方依据证明 Claude Code 会执行 `agents/openai.yaml` 中的这一策略。[Claude Code 调用控制](https://code.claude.com/docs/en/skills#control-who-invokes-a-skill)

因此，把当前目录复制给 Claude Code，不能保证 README 所说的“Brief、Review 保持手动调用”。这是宿主配置可移植性问题，不能据此说 Claude 无法理解正文。若仓库只面向 Codex，说明支持范围即可；若要保证 Claude Code 同等行为，应在打包或宿主设置层补对应控制，并测试手动入口、自然语言提及、Align 返回已发起 Brief 三种情况。无需为模型分别复制整套正文。

同样，Astra 指南要求明确用户指令与 Skill 指南的优先关系。本仓库在多个局部条款尊重委派和原请求，却没有统一写出这层关系。在当前 Codex 环境中，宿主已经提供该规则，不能据此判运行时缺陷；跨宿主移植时应核对实际优先级。真实外部授权条件与普通 Skill 流程建议也需要保持区别，不能一并由模型自行豁免。

**确认门槛偏严格，首先是产品选择。** 这里定义的 Brief 是已采用合同，因此对未定的保留期、授权主体或集成结果要求决定，有实质理由。若将它自动套到普通开发、随口讨论或可逆草稿上，才会额外增加流程。当前版本已限制触发、允许直接工作、接受明确委派，也修掉了重复确认的旧问题；这轮没有新的运行证据证明它仍普遍阻塞。不能用旧版本故障描述现版，也不能因为更强模型“应该懂”就取消必要决定。

仓库自身的[Astra 适配记录](2026-09-05-astra-adaptation.md)报告主文件英文词数约增加 12.8%，并保留过宽 guard 误触发后的收窄过程。这说明累积压力真实存在，同时也说明维护者已经在抑制它。最有价值的下一步是合并相同规则、检验净收益，继续追加“防止防御性堆积”的规则只会放大这个问题。

社区材料支持这种有条件的判断。HumanLayer 警惕把常驻指令写成不断追加的行为补丁，推荐按需引用；该经验主要针对 `CLAUDE.md`，不能直接转换成 Skill 的统一字数上限。[HumanLayer 原文](https://www.humanlayer.dev/blog/writing-a-good-claude-md) Simon Willison 用极短工程提示激活模型已有知识，说明基本工程方法无需重复教学；它也不意味着本仓库独有的合同与来源语义可以省略。[Simon 原文](https://simonwillison.net/guides/agentic-engineering-patterns/first-run-the-tests/)

ETH／LogicStar 的 AGENTS.md 论文 v2 观察到额外指令常增加探索、测试与成本，却通常没有显著改善成功率；其附录也没有发现简单的长度—成功率关系。研究对象是较早模型上的 Python 仓库任务，不能证明这三个 Skill 有害。它提供的是对照实验的理由。[原论文 v2](https://arxiv.org/html/2602.11988v2)

特别是[盲交接 runner](../../evals/scripts/run_mission_brief_blind.py:160)明确要求读取、解释或提出路线，不修改工作区。这是有效的“理解与交接”测试，不能被计为“接手并做完”的实验。当前对照主要是旧版与新版 Skill，不能回答整个 Skill 相对模型原生能力的净收益。

另外，按自身 rubric 通过，证明的是已选产品规则被遵守。如果某条规则本身要求多一次不值得的确认，模型忠实遵守也可以通过。发布一致性检查、产品规则是否值得存在、模型能力是否被充分利用，是三个不同问题。

**下一轮应优先验证价值，再决定删多少。**

保留三项职责、四项合同核心、来源状态、条件引用和比例适当的验收。先合并上述重复段落，不新增通用审批、反复自检或模型专属流程。若承诺 Claude Code 支持，先补宿主调用控制。

随后复用已有 fixture 与 rubric，选择少量未参与这轮改写的真实任务，比较无 Skill、现版、合并重复后的简版。至少包含清楚的小任务、真正的产品歧义、明确委派后的修正、临时调查保全，以及一次允许新 Agent 真实执行并交由 Review 检查的交接。各模型分别固定宿主、输入、权限和有效推理档位；跨厂商同名 effort 不当作等量思考。

评价同时看结果正确性、丢失的关键义务、无必要确认、越出委托范围、阅读／工具调用成本和完成时间。若简版减少流程且不损害这些结果，删除对应重复；若差异不稳定，保留现版即可。无需为了证明精简而规定必须削减某个百分比，也无需把所有新 API 功能写进 Skill。

综合静态内容、官方建议和可取得的本地证据，当前最合适的定位是：**一套在 Astra 上有可追溯回归依据的结果合同与验收工作流；有局部可压缩的确认／交接文字，尚未证明跨最新模型的最优性。**

**附件文章补充复审：从文字去重，进一步检查流程是否必要。**

根据用户随后提供的 [Rethinking skills and prompts for GPT-6 Astra.pdf](</Users/admin/Downloads/Rethinking skills and prompts for GPT-6 Astra.pdf>)复审同一运行时版本。已提取正文并逐页查看全部四页，包括文字提取遗漏的两幅好／坏示例图。文章及其中的示例提示词均作为审阅材料；本轮没有修改 Skill、产品规格或评估，也没有新增模型运行。

这篇文章使建议进一步聚焦：一条旧指令即使仍能被准确执行，也未必值得继续要求。应逐项检查它解决的是本工作流独有的问题，还是在替新模型安排已有能力能够完成的判断。前次评审关注重复文字，这次还需要检查重复文字背后的固定流程和默认停点。

| 第 2 页：减少详细行程式指令，让模型处理语义和歧义 | Align 同时规定五个阶段、四个阶段完成判据、逐项提问步骤，以及两份近似的摘要／交接清单 | Align 是最值得做结构精简的对象，保留领域规则和结果条件，让对话顺序按当前缺口决定。编号本身不是缺陷，逐项安排输出动作才是重点。 |
| 第 3 页及配图：阅读应由任务需要触发 | Brief 要求 enough workspace evidence，Review 只读 enough implementation record；没有每次编辑先读全仓文档的要求 | 符合。恢复合同本身是这项任务必需的工作，不应删除。维护者材料也没有进入最小运行时包。 |
| 第 3 页：旧模型时代的泛化验收鼓励可能导致多余测试 | Review 已规定证据复用、比例适当的补查和停止条件；Brief 要求的是合同可被证伪 | 这些要求与泛化“做完再查一遍”不同，继续保留。需要澄清的是 Brief 最后的 blind handoff 名称是否会被理解为额外强制独立验收。 |
| 第 4 页：检查确认边界与提前停下是否真有必要 | 原请求恢复和已授权动作已有规则；Align 的清楚任务用例仍明确要求初始采纳 | 值得挑战这一产品停点。前次修复减少了修正后的再次确认，尚未回答初次确认在完全明确的输入上是否需要。 |

以上字符数按 description 字段本身统计，不是 token 数；文章没有提供统一字符阈值或本仓库的性能实验。

**优先建议一：重新评估“完全明确的委托仍需初始确认”。**

[Align 评估第 1 例](../../evals/mission-align.md:33)给出明确的 Safari 登录回归及 Chrome／鼠标兼容边界，仍要求一次明确确认；[Eval Pack](../../evals/mission-align-pack.json)的 `a-10000001` 也把初始采纳写进 rubric。[现行产品规格](../specs/mission-align.md:28)则要求采用当前完整摘要及路由／拓扑。因此，这个停点不能被解释成模型误读或偶发啰嗦。

可以试验的产品规则是：用户已明确给出全部重大决定，且 Agent 的综合没有引入新的结果、边界、授权或实质路由选择时，直接交接；只有新的重大解释、未委派的选择或真实权限冲突才提问。用户明确要求“先给我确认”时仍按其要求；单纯沉默、含糊认同和试探性建议也不能作为新决定。

这是一项产品规则候选，需要规格与 rubric 一致调整后再比较结果。仅删除运行时确认要求、继续用旧 rubric 评分，会把预期改善判成失败。对于只要求对齐的用户，直接交接仍是完成本次对齐，不自动开始实施或调用另一个手动 Skill。

**优先建议二：减少 Align 对对话过程的逐项规定。**

[第 52–58 行](../../mission-align/SKILL.md:52)规定每个重大歧义要解释不清之处、所有受影响维度、候选、推荐及最小问题；[第 72 行](../../mission-align/SKILL.md:72)与[第 90 行](../../mission-align/SKILL.md:90)又规定摘要和交接字段。即使每条都合理，组合起来仍可能让一个简单决定产生完整解释流程。

下面只是局部写法示意，展示如何保留行为要求而减少步骤编排，不是整份 Skill 的替换版本：

```text
Expose unresolved choices that materially change the commission. Explain the
consequence and recommendation only as needed for the user's decision.
Preserve adopted decisions and delegated choices. Use the adopted synthesis
as the handoff, adding necessary source pointers and remaining uncertainty.
```

四项 Contract Core、来源状态、真实 Mission 0 判断、已采用决定和委派范围仍是本系统的专有知识，应保留。是否逐项展示内部准备状态、是否分别再写确认摘要和交接摘要，则应由对话需要决定。预期收益是更少流程负担；本轮没有实测证明收益幅度。

**优先建议三：精简自动发现入口，但不扩张或偷换用途。**

[Align description](../../mission-align/SKILL.md:3)可以测试更短的候选，例如：

```yaml
description: Align an unclear or contested Mission commission before briefing.
```

正文继续负责判断是否值得写 Brief、一个结果或父子结果如何安排、哪些问题需用户选择。该候选需要保留“普通实现不触发、复杂 Brief 歧义可进入、明确手动调用可用”的发现行为；较短并不自动更准确。Brief 和 Review 的描述已短且采用手动入口，没有必要为了格式统一而重写。

**次要建议：区分作者的交接检查与真实盲读实验。**

[Brief 第 101 行](../../SKILL.md:101)把四个作者自查问题称为 blind handoff，但实际看不到原始会话的独立读者是在发布评估中运行。[盲读 runner](../../evals/scripts/run_mission_brief_blind.py:160)明确建立单独输入。运行时名称有潜在歧义：可能让模型把作者自查升级成每个小 Brief 都要额外启动独立 Agent，也可能让作者自查被误称为已获独立证据。

建议将运行时这段表达为交接就绪条件，保留四个问题的核心语义；只有任务或证据要求独立读取时才进行真实盲读。这里指出的是文本歧义，不是本轮已复现的额外子代理调用。Review 现有按需独立性条款已经限定条件，无需追加第二套验证门槛。

**本次建议的实施顺序。** 先试验 Align 的短描述、合并摘要／交接及压缩逐步对话要求；再单独评估初始确认这项产品规则，避免把语义改变混入文字精简。保留前次建议的简版对照，优先查看误触发、额外确认和原请求是否继续，同时检查重要信息及授权有无丢失。Brief 保留合同与条件引用，Review 保留实质证据和停止条件。

文章第 4 页对“事先定义完成”的强调，反而强化了 Mission Brief 的存在理由：执行者应能从合同知道何时算做完。最值得减少的是已经明确的工作开始或继续之前，人为增加的重复决定与流程；无需削弱结果定义来换取短文本。
