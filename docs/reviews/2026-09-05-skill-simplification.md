## 实验修正与局限

冻结基线及 S1／S2 快照保留。P1 的旧 Safari 输入混淆了“先实施”与“先交接”；明确委托后 B 和 S1 都直接交接，旧 rubric 的首次确认要求与实际正确行为不一致。P2 的多轮输入改为明确要求先确认，并澄清订单业务终态失败的含义，避免把实质歧义当作多余提问。

早期执行试跑暴露了 Python 运行时访问问题、CLI 新参数与旧未知参数的范围冲突，以及“畸形输入”是否包含结构校验的歧义。修正面向所有组的输入与环境，没有为这些问题修改 Skill；原试跑作为诊断保留。最终比较采用输入 1.0.2。

[执行入口](../../evals/scripts/run_mission_handoff_execution.py)复用现有 harness，单独采集交付裁决，避免把“审查做对了”当作“交付通过了”。无合同时才在原会话补发一次冻结答复；逐次原始问答仍保留。首轮六条均未用到该补答分支，其真实模型行为未被这六条实测覆盖。
